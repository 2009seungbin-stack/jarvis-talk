원리 1듣기

소리가 글자가 되기까지

마이크를 계속 녹음해서 보내지 않아요. 사람 말소리가 있는 구간만 잘라서 받아쓰기 프로그램에 넘겨요.

Silero VAD v5vad-web 0.0.30whisper.cpp b5130 · CUDA 12.4ggml-large-v3-turbo-q5_0 · 574MB
원리
  1. 음성 감지: 마이크 소리를 약 0.03초 조각으로 잘라, 작은 AI가 '사람 말일 확률'을 매김. 기준을 넘으면 녹음 시작, 말이 끝나고 잠깐 조용하면 녹음 끝. 말 앞 0.3초도 함께 붙임
  2. 전송: 잘라낸 소리(1초에 16,000개 숫자)를 서버로 보냄
  3. 소리 그림: whisper가 소리를 시간별·높낮이별 세기 그림(스펙트로그램)으로 바꿈
  4. 인코더: 트랜스포머가 그 그림을 읽고 소리의 특징을 숫자 묶음으로 정리
  5. 디코더: 그 특징을 보면서 글자 조각(토큰)을 하나씩 예측. "자비스" → "," → "날씨" …
  6. 정리: 조용할 때 whisper가 지어내는 "시청해 주셔서 감사합니다" 같은 문장을 지우고, 자주 틀리는 이름을 고침
자비스에서는
  • turbo: 원래 large-v3에서 글자를 만드는 쪽(디코더) 층을 32개에서 4개로 줄여 훨씬 빠르게 만든 버전
  • q5_0: 모델 숫자를 5비트로 줄여 저장(양자화). 약 1.6GB → 574MB
  • 힌트 문장: "자비스, Godot, 메모장…" 같은 단어를 미리 알려 줘서 이름 철자를 맞춤
원리 2앱 · 서버 · 호출어

앱과 서버, 그리고 "자비스"

바탕화면 캐릭터와 작업 창은 사실 웹 페이지예요. Electron이 그걸 프로그램 창으로 띄우고, 뒤에서 Python 서버가 소리·글·명령을 주고받아요.

Electron 44Python 3.10StarletteWebSocket
원리
  1. Electron = 크롬 엔진(Chromium) + Node.js. 웹 페이지를 투명하고 항상 위에 있는 창, 트레이 아이콘, 단축키가 있는 프로그램으로 만듦
  2. 로컬 서버: 창 안의 페이지는 127.0.0.1:8180에서 옴. 127.0.0.1은 '이 컴퓨터 자신'이라 다른 기기에서는 접속 불가. 접속 토큰도 확인
  3. WebSocket: 연결을 열어 둔 채 소리 조각, 받아쓴 글, 답 글자, 음성, 표정 명령이 양방향으로 계속 오감
  4. 호출어: 별도 AI 없이, 받아쓴 글이 "(헤이·야) 자비스(야·아)"로 시작하는지 규칙으로 검사. 아니면 버림
  5. 이어 말하기: 자비스가 대답한 뒤 20초 동안은 호출어 없이 말해도 됨. 단축키나 캐릭터 클릭으로도 깨움
  6. 즉시 명령: "작업 멈춰"는 AI를 거치지 않고 서버가 바로 처리
원리 3AI 모델

AI 모델은 어떻게 대답할까

AI 모델은 지금까지의 글 다음에 올 가장 그럴듯한 조각을 하나씩 고르는 일을 아주 빠르게 반복해요. 대답도, 도구 사용 요청도 이렇게 만들어져요.

원리
  1. 토큰화: 글을 조각(토큰)으로 쪼개고 각 조각을 번호로 바꿈
  2. 맥락 읽기: 지시문 + 대화 + 도구 결과 + 스크린샷을 한꺼번에 읽음. 한 번에 읽을 수 있는 양이 컨텍스트(자비스 설정 기준 Claude 20만 토큰)
  3. 예측: 다음 토큰이 될 확률을 모든 후보에 대해 계산 → 하나 고르고 → 붙이고 → 다시 예측
  4. 생각: 대답 전에 먼저 속으로 계획을 씀. 그 양이 effort. 지금은 high
  5. 스트리밍: 다 쓸 때까지 기다리지 않고 만들어지는 대로 보냄 → 첫 문장부터 바로 말하기 시작
자비스에서 쓴 두 방식
  • 내 PC (10.06~10.13): llama.cpp가 GGUF 모델을 그래픽카드로 실행. 큰 모델은 4비트·2비트로 줄여서 넣음. Flash-Next 125B는 MoE 구조라 한 번에 6B만 계산하고, 나머지는 RAM과 SSD에 두고 Strata 엔진으로 돌림

원리 4도구 호출

글만 쓰는 AI가
프로그램을 실행하는 방법

AI 모델은 글만 쓸 수 있어요. 그래서 "이 도구를 이렇게 써 줘"라는 정해진 형식의 글을 쓰면, 프로그램이 대신 실행하고 결과를 다시 AI에게 보여줘요.

원리
  1. 도구 목록: 대화 맨 앞에 도구마다 이름, 설명, 받을 값의 형식(JSON 스키마)을 줌
  2. 호출 작성: AI가 답 대신 tool_use 블록을 씀
  3. 실행: 에이전트 엔진이 그걸 읽고 실제로 클릭·명령·파일 작업
  4. 결과 전달: 결과(글, 스크린샷)를 tool_result로 대화에 붙여 다시 AI에게
  5. 반복: AI가 결과를 보고 다음 도구를 쓰거나 최종 답을 씀. 기초 2장의 네 단계가 바로 이것
AI → {"type":"tool_use","name":"computer", "input":{"action":"click","x":640,"y":360}} 엔진 → {"type":"tool_result","content":[스크린샷]}
예전과 지금
  • 예전: Goose → 게이트웨이 → Playwright·Windows 조작 도구. 이 연결 규격이 MCP. 도구 55개, 설명만 22,990자
  • 지금: Agent SDK 기본 도구(Bash, Read, Write, Edit, Glob, Grep, WebSearch, WebFetch 등) + 직접 만든 2개(computer, ask_user)

Claude Agent SDK

개발자용 AI 도구인 Claude Code의 엔진을 다른 프로그램에 넣을 수 있게 꺼낸 거예요. 자비스 Linux 안에서 Python 프로그램으로 돌아가요.

claude-agent-sdk 0.2.174Claude Code 엔진 2.1.310jarvis_agent.pyCLAUDE.md
요청 하나가 처리되는 순서
  1. 시작: Windows가 wsl.exe로 Linux 안의 jarvis_agent.py --serve를 켬. 준비되면 "ready"
  2. 지시문: Claude Code 기본 지시문 + 자비스 지침서(CLAUDE.md: 정체성, 이 컴퓨터 설명, 일하는 법, 말투, 경계)

  4. 반복: 모델 호출 → 도구 실행 → 결과 붙이기를 SDK가 자동으로 반복
  5. 실시간 보고: 말, 도구 사용, 결과를 한 줄씩 내보냄 → 앱이 대화창·화면·커서에 표시

  • 기억: 세션 번호로 다음 대화에서 이어 가고(resume), 오래 남길 요령은 ~/notes에 스스로 적음

원리 6자기 컴퓨터

Windows 안의 Linux 컴퓨터

WSL2로 Windows 안에서 진짜 Linux를 작은 가상 컴퓨터로 돌려요. 모니터 없이 메모리 안에 화면을 만들고, 그 화면을 앱으로 송출해요.

WSL2 · Jarvis-UbuntuXvfb :7openboxChrome · LibreOfficex11vncnoVNC 1.7.0
아래층부터 위층까지
  1. WSL2: Windows의 Hyper-V 위에서 도는 가벼운 가상 머신. 진짜 Linux 커널이 들어 있음
  2. 격리: Windows 드라이브 연결 안 함, Linux에서 Windows 프로그램 실행 불가, 관리자가 아닌 사용자 jarvis, 별도 네트워크(NAT)
  3. Xvfb: 모니터 없는 가상 화면 :7(1600×900). 프로그램들은 진짜 모니터인 줄 알고 그 위에 그려짐
  4. openbox: 창을 띄우고 옮기는 창 관리자. 그 위에 자비스 전용 Chrome(CDP 포트 9333)과 문서 프로그램
  5. x11vnc: 화면 :7의 변화를 VNC로 내보냄(포트 5907)
  6. noVNC: VNC를 웹 페이지 안에서 보여주는 프로그램 → 앱 오른쪽 패널. '직접 조작'을 누르면 내 마우스가 그 화면으로 감

원리 7화면 조작

보고, 좌표를 계산하고, 누르기

직접 만든 computer 도구 하나로 스크린샷, 마우스, 키보드를 모두 처리해요.

ImageMagick importPillowxdotoolxclip
클릭 한 번의 과정
  1. 찍기: ImageMagick이 가상 화면 전체를 찍음(1600×900)
  2. 줄이기: Pillow로 1280×720으로 줄여 AI에게 보냄. 이미지가 작을수록 빠르고 토큰도 적게 씀
  3. 판단: AI가 그림을 보고 "검색창은 (640, 300)" 같은 좌표로 답함
  4. 변환: 1.25배 해서 실제 화면 좌표로 (640, 300) → (800, 375)
  5. 입력: xdotool이 가짜 마우스·키보드 신호를 가상 화면에 넣음. 클릭, 더블클릭, 드래그, 스크롤, 단축키
  6. 한글: 키 입력으로는 한글이 깨지기 쉬워서 xclip으로 클립보드에 넣고 Ctrl+V
  7. 확인: 0.6초 기다렸다가 다시 찍어서 결과를 AI에게
  • 내가 '직접 조작' 중이면 도구가 손을 떼고 최대 10분 기다림
  • 정확한 숫자가 필요하면 화면 대신 Chrome의 CDP로 페이지 내용을 직접 읽음(Playwright). 첫 과제에서 자비스가 스스로 고른 방법

Supertonic 3 (Supertone)ONNX · CPU 4스레드음색 JarvisBlend
원리

AI가 멋대로 하면 어떡해?

자기 컴퓨터 안에서는 자유롭지만, 사람에게 영향이 가는 순간에는 반드시 멈추고 물어요.

  1. 질문 카드: 메시지 보내기·게시·결제·로그인 직전, 자비스가 직접 물어요. 카드 버튼, "응/아니", 또는 그냥 말("시간을 11시로 바꿔서 보내")로 답해요
  2. 직접 조작: 내가 화면을 잡으면 자비스의 조작이 멈추고, 돌려주면 화면을 다시 보고 이어가요
  3. "작업 멈춰": 말 한마디로 즉시 중단
  4. 격리: 자비스 컴퓨터는 내 파일과 Windows 프로그램에 닿지 못해요
  5. 되돌리기: 백업이 있고, 설정 하나로 예전 방식으로 돌아갈 수 있어요
