Ⅱ 탐구 목표

AI가 컴퓨터 일을 끝까지 해낼 수 있을까?

탐구 질문: 말로 시킨 일을 AI가 스스로 끝까지 처리하게 하려면 무엇이 필요한가

① 말로 시키고 말로 듣기받아쓰기, 목소리, 호출어
② 실제 컴퓨터 조작브라우저, 프로그램, 파일을 직접 다루기
③ 보이고, 멈출 수 있게하는 일을 실시간으로 보고, 위험한 일은 묻고, 언제든 중단
④ 살아 있는 비서듣기·생각·작업·말하기 상태가 한눈에 보이는 캐릭터
  • 탐구 질문은 "AI가 말로 시킨 일을 스스로 끝까지 처리하게 하려면 무엇이 필요한가"입니다.
  • 목표 기능 네 가지: 음성 대화, 실제 컴퓨터 조작, 투명성과 안전장치, 상태가 보이는 캐릭터.
  • 평가 기준: 실제 과제(예: 웹에서 정보를 찾아 엑셀로 정리)를 사람 도움 없이 끝까지 하는가.
Ⅲ 이론적 배경 · AI 에이전트

생각하고, 도구를 쓰고, 확인하고, 반복한다

생각AI 모델이 다음 행동을 정함도구클릭 · 입력 · 명령 · 파일확인스크린샷과 결과를 봄반복끝났다고 판단할 때까지
  • AI 모델 자체는 글을 읽고 다음 글자 조각(토큰)을 예측하는 프로그램입니다. 혼자서는 컴퓨터를 만질 수 없습니다.
  • 그래서 모델에게 도구를 쥐여 주고, 생각 → 도구 사용 → 결과 확인을 스스로 반복하게 만든 프로그램 구조를 'AI 에이전트'라고 부릅니다.
  • 모델이 아무리 똑똑해도 도구가 부족하거나 지시가 엉키면 이 반복이 제대로 돌지 않습니다. 이 점이 탐구 과정의 핵심이 됩니다.
Ⅲ 이론적 배경 · 도구 호출

AI는 요청을 쓰고, 엔진이 실행한다

tool_useAI가 쓰는 실행 요청tool_result결과를 다시 AI에게MCP도구를 꽂는 표준 규격
  • 모델은 글만 씁니다. 대화 앞에 도구 목록(이름, 설명, 받을 값의 형식 = JSON 스키마)을 주면, 모델이 tool_use라는 정해진 형식의 글을 씁니다.
  • 에이전트 엔진이 그걸 읽어 실제로 실행하고, 결과(글, 스크린샷)를 tool_result로 대화에 붙여 다시 모델에게 보여줍니다.
  • MCP(Model Context Protocol)는 이런 도구를 AI 프로그램에 꽂는 표준 규격입니다.

Ⅴ 탐구 과정 · 문제 1 (10.09)

AI가 그림을 못 본다고 했다

171.9초고치기 전, 실패18.6초고친 뒤, 성공원인이미지가 "omitted"라는 글자로 바뀌어 전달
  • 증상: 그림이나 차트를 확인하라고 시키면 계속 실패.
  • 원인: Goose는 자기 목록에 없는 모델에게 이미지를 보내지 않고 "omitted(생략)"라는 문장으로 바꿔 보냄.
  • 해결: 시작할 때마다 자비스 모델을 그 목록에 등록. 뒤 화면은 고친 뒤 자비스가 직접 그린 막대그래프.
  • 알게 된 점: 중간 프로그램이 AI에게 무엇을 바꿔 보내는지 직접 열어 봐야 한다.
Ⅴ 탐구 과정 · 문제 2 (10.09)

같은 실패를 160번 반복했다

160번막힌 도구에 같은 시도3번연속 실패하면 멈춤숨기지 않기실패를 화면에 표시
  • "모델 바꾸는 중" 표시가 지워지지 않아 모든 도구가 막혔는데, AI는 그걸 모르고 같은 호출을 160번 반복.
  • 수정: 같은 실패 3번이면 멈추고, 활동 카드에 실패를 그대로 표시(오른쪽 화면). 클릭 위치를 보여주는 커서도 추가(왼쪽 화면).
  • 이런 문제를 하나씩 고쳤지만, Claude로 바꾼 뒤에도 일을 잘 못 하는 문제는 남았습니다.

비용이 든다과제 하나에 약 $0.04~$0.41. 내 PC 모델은 무료였다
전체 흐름 검증이 남았다앱에서 말로 시키는 전 과정을 실제 사용 화면에서 아직 확인하지 못했다
